## S1 归一尺寸（三步走，全部 NEAREST，零混合）

```powershell
& $py <repo>\tools\prep_canvas.py `
     --ref "$rd\01-ref-src.png" --depth "$rd\02-dep-src.png" --outdir "$rd"
# 可选：--max-mp 2.0（默认）   --depth-black-bg（仅当深度源图是实景背景，见 §5.4）
# 产物：ref_norm.png（画布尺寸、居中补白） / depth_raw.png（原尺寸原样） / prep.json
```

| 步骤 | 规则 | 判据 / 坑 |
|---|---|---|
| **① 参考图裁 alpha 空白 + 合白底** | `im.split()[-1].getbbox()` 裁掉透明边（实测 `1538×2724 → 1530×2720`）；RGBA 必须 `alpha_composite` 合成白底 | **只许 NEAREST**：bilinear/area/Lanczos 会把金线、宝石、菱形纹糊掉；不合成白底则透明被读成黑 → 出黑框 |
| **② 画布高取参考、比例取深度** | **高 = 参考裁剪高在 2 MP 内的最大 16 倍数**（本例 `1632`）；**宽 = 高 × 深度宽高比**（`1632×0.75 = 1224 → 1216`，画布比例 0.745 ≈ 深度 0.75） | 这样**深度零变形**；反过来"画布取参考比例"（0.564）会把 0.75 的深度横向压窄、纵向撑满（`sx6_a`：人物贴边、上下被裁） |
| **③ 参考 contain 进画布补白；深度原样喂** | 参考等比缩进画布居中补白（`918×1632`，左右各 149，`MOSS_REF_ALIGN` 侧不会变形）；深度**不缩放、不补黑、不 tight**，直接交 `--depth-map` | **深度不要为凑画布去 contain/tight/补黑** —— 上方留黑处会长出第二个人（`jump` 轮实测）；`tight` 还会把横向宽姿势的手臂裁掉 |

实测（`sx06` 腾空跃起，2026-11-08 定稿）：

| 版本 | 画布 | 深度处理 | 结果 | 锐度 |
|---|---|---|---|---|
| `sx6_a` | 1056×1888（参考比例 0.564） | 原样被 fit 拉伸 | 姿势对、单人，但人物撑满贴边、上下被裁 | 373 |
| **`sx6_b`** | **1216×1632（比例 0.745 ≈ 深度）** | **原样，几乎零变形** | **姿势全对、全身入画、留白均衡、比例自然** | 275（fast 8 步上限，非构图问题） |

> 旧做法（`prep_normalize.py` 的 contain / height / cover / tight + 背景压黑）已退役：三者都会改动深度图几何，实测要么长出第二个人、要么把人裁掉。相关反例与数据保留在 **§5.4 / §5.7 / §5.8**，只在"深度背景不干净"时沿用其中的**压黑**一步。

**显存算术**（决定成败）：`ref_kv ≈ 28 × 2 × n_ref × 4096 × 2 B ≈ 0.44 MiB/token`。16320 tok = 7.50 GiB 必 OOM；`MOSS_REF_POOL=2` 把 n_ref 除 4。**环境变量必须设在 8190 服务进程**（设调用端 shell 无效）。

## S1.5 GrabTag 标注参考图（**必须在 S1 之后**）

> **顺序铁律：先归一尺寸，再标注。** `plan --ref` 必须用 `ref_norm.png`、`--size` 必须等于归一后的 `W×H`。否则 `rect / color` 是从原图坐标算的，与画布错位（原图 4.59 MP → 归一 1.99 MP 时坐标会偏 1.5 倍）。
>
> **姿势铁律：色图分区是"参考图坐标"，不是"角色坐标"。** 深度姿势与参考姿势差异大时，`--color-map` 会把某个区的形状投射到错误的解剖位置（实测 P012 芭蕾抬腿：`sleeve_r` 区在参考图右上，而成图那里是抬起的腿 → 右上凭空长出一片袖子和一只冰鞋）。此时二选一：① **不传 `--color-map`**，只靠 tag 块文字取形（`v403` 已验证不乱长）；② 只标**不随姿势移动的躯干区**（`bodice` / `sash` / `hair` / `veil` / `drape`），四肢区（`legs` / `sleeve_*` / `shoes`）留空不标。

```powershell
$gt = "$rd\gt"
& $py <repo>\grabtag.py plan `
     --ref "$rd\ref_norm.png" --spec "$rd\spec.json" `
     --size <prep.json 的 canvas，如 1216x1632> --for both --max-items 20 --min-area 0.002
& $py <repo>\grabtag.py build --dir $gt --sort y
# 需要核对"哪些 tag 参与"时（S2 写完后）
& $py <repo>\grabtag.py active --dir $gt --prompt-file "$rd\prompt.txt"
```

| 产物 | 内容 | 用在哪 |
|---|---|---|
| `tags.json` → `ref_tag` | **tag 串**：一个字符串内用英文逗号分隔多个别名（`trousers, harem pants` / `bodice, crop top` / `right sleeve` / `belt, sash`） | **检索词**：写进 `<|身体|>` 的位置引用与正文（`active` 按任一别名的子串命中） |
| `tags.json` → `name` | 该区的短名、**单 token**（`legs` / `sleeve_r` / `sash_point`） | **`<|…|>` 块名必须用它**（块名不许带空格与逗号，用 `right sleeve` 会 HTTP 400） |
| `tags.json` → `crop` | 该区的像素裁片 | 只在第二段局部精修时作 `--image` 用，不进全局 |
| `rect` / `color` | 该区的位置与 ID 色 | 第二段转 0/255 掩码 |
| `cm.png` | 分区色图（同一 ID 色铺满区） | S3 可选 `--color-map cm.png`（**给了才走像素通道**） |
| `regions.json` / `montage.png` | 机器可读分区表 / 目视拼接图 | 核对用 |

**坑（实测）**：
- **`spec.json` 的 rect 是"这张参考图"的坐标，不是角色的**：换了参考图或姿势必须重标。实测把 `reg_ice3` 的 spec 直接套到 P012（芭蕾抬腿）上 → 右上角的 `sleeve_r` 区落在空白处，成图右上角凭空长出一片袖子。
- `spec.json` 要手写：每项 `name / ref_tag(可给多个别名) / rect(归一化 0–1) / fit`。范本 `C:\MOSS-Deploy\work\reg_ice3\spec.json`（11 区）。
- **`build` 必须 `--sort y`**：新默认按 area 降序，item 顺序变化会让出图结果变。
- **`active` 只认英文 ref_tag 原词**：中文（「宽腰封」）命中 0/11；`bodice, crop top` 这种带别名的才算命中。
- 命中 >2 张时只打印 `! 命中 N 张，超过 2 张上限：接线时请按 area 截断` —— 是**软提醒**，不是硬限制。
- `rect` 写到 `y1=1.0` 会 `[warn] 框超出画布`（无害）。
- `plan` 会自动把 `cm.png` 复制成 `C:\MOSS-Deploy\ComfyUI\input\regcap_<dir>.png`（LoadImage 只认 input 目录）。

## S2 编写提示词

### 2.0 三件事分工（v401 / v403 / v405 三组实测反证）

| 你写的东西 | 它实际控制什么 | 反证 |
|---|---|---|
| **tag 名字**（ref_tag 原词） | "有这件东西" + "它长什么样（从参考图取形）" | v403/v404 删掉 tag 内全部描述、只留 `bodice, crop top` 等 → 水晶球/白花/腰封菱形/垂尾 V 尖/两臂袖子/鞋/辫子**全在**，但冰退成薄纱 |
| **描述词**（颜色/材质/透明度/结构） | 材质、颜色、透明度、可见行为 | v401 把 tag 内描述删光后同一处变"浅蓝纱"；v400 原 14 块（每块带材质描述）才有真冰与深紫蓝菱形 |
| **构图约束**（单人/占满/镜头/留白） | 画面占比与画面边界 | v405 只写"画面里只有一个人" → 人物占宽 **67.4%**（有 layout 时 98.6%），四周大片留白 |

⇒ **一句话总结：tag 说"是什么"，描述词说"是什么材质"，构图句说"占多大"。三者缺一，缺哪样丢哪样。**

### 2.1 块结构与块序

- 语法：`<|块名|>内容<|/块名|>`，块之间换行分隔，**不要嵌套**。
- **块序 = 权重**（Qwen3.5 左→右单向因果注意力，前面的块影响后面的块）：
  `构图 → 身体 → 各 tag 块（按视觉面积从大到小）→ 背景`
- 块名统一用**英文**，且与 `tags.json` 的 `ref_tag` 完全一致（`active` 子命令只认英文原词；中文命中 0/11）。
- 单块字数：**80–160 字**。旧 SOP 写"≤110"，但 V200 实测双臂/大腿 145–156 字反而最好；超过 ~200 字开始互相吃掉。

#### 2.1.1 **首选写法：11 部位分区 + tag 词汇**（2026-11-08 实测定稿）

> **三条写法禁则（2026-11-08 实测）**
> 1. **不要写「身高约等于头高的 8 倍」** —— 去掉后脸型自然、不再娃娃脸；`<|身材|>` 只写「肩膀窄、腰窄、胯宽、腿细长，脖颈与四肢都细」+ 数量锁。
> 2. **不要写「二次元插画的脸」** —— 这句把脸推向圆润娃娃脸；只写「脸露出来、不被纱遮住，眼睛清楚、形状像动画里的眼、带一点深琥珀色，脸颊上有一层很淡的粉」即可。
> 3. **脚/手的位置按深度图实际描述**，不要用文字去"纠正"深度图没给的姿势：写「鞋并排摆在她身前的地面上」→ 鞋被脱下摆在地上；写「并排收在正前方、都穿在脚上」而脚被身体挡住 → 鞋直接消失。**文字只能决定"画不画"，不能决定"在哪"。**

> User said (m19374)：「提示词写法错了，我们回归到11部位写法，但是涉及到tag的词汇使用tag」。

**块名用 11 个身体部位**（中文单 token，沿用 `07` 的器官分区），**正文里凡涉及服装/器物一律写成 `tags.json` 的 `ref_tag` 别名**（`（bodice, crop top）`、`（trousers, harem pants）`、`（belt, sash）`…）：

```
<|构图|> → <|身材|> → <|头部|> → <|颈肩|> → <|双臂|> → <|胸部|>
→ <|腰腹|> → <|大腿|> → <|小腿|> → <|脚部|> → <|背景|>
```

- 每块 = 该部位的形体描述 + **落在该部位的 tag 别名（带材质描述）**。例：
  - `<|双臂|>…两条半透明蓝白菱格的（left sleeve）（right sleeve）套在两条胳膊上，菱格里嵌深蓝宝石，袖口收在金色宽镯上。画面里只有她的一双手、两条手臂。`
  - `<|大腿|>两条腿外面各包着一层冰…裤子是宽松的灯笼形（trousers, harem pants），布料从浅蓝渐变到白，脚踝处收口。`
- **为什么比"每个 tag 一个块"好**：14 个 tag 块会把注意力摊到 14 个名词上、器官本身没有块、姿势与体态无人描述；11 部位分区把权重还给身体，tag 只作"这件东西叫什么"的指针。
- 实测（`20261108-0401-s2-grabtag-v2`，同 seed 同深度）：
  | 版本 | 写法 | color-map | 结果 |
  |---|---|---|---|
  | `g2_a` | 14 个 tag 块 | ✅ | 单人，但**右上凭空一片袖子、右下多一只冰鞋**（色图区按参考坐标投射到抬起的腿上） |
  | `g2_b` | **11 部位 + tag** | ❌ | **双人**（参考站姿 + 深度抬腿各画一个），颜色偏淡（饱和 42.9） |
  | `g2_c` | **11 部位 + tag** | ❌ + `--depth-fit tight` | **单人、姿势准、纹样全**（饱和 79.9），代价抬起的右脚出画 |

- **三条配套结论**：
  1. **首选 11 部位 + tag 词汇，且不传 `--color-map`** —— 悬空部件与错位都消失。
4. **脸要"二次元"，不要"写实"** —— `<|头部|>` 写「二次元插画的脸 / 眼睛形状像动画里的眼 / 脸颊一层很淡的粉」就出 2D 脸；写「五官完整清楚、鼻梁、嘴唇、腮红」会直接跳到 3D 写实脸（皮肤毛孔、鼻梁立体、嘴唇写实）；负向里放 `faceless, blank face, no eyes` 同样把模型推向写实（否定式招来"脸"的强特征）。实测同一张深度图：`kneel_a` 无细节写法 → 脸无五官；`kneel_b` 写实写法 + faceless 负向 → 3D 写实脸（锐度 177）；`kneel_c` 二次元写法、负向不加 faceless → 2D 脸成立（锐度 359）。

  2. **姿势与参考差异大时必须 `--depth-fit tight`**（占高拉到 100%），否则留白处会长出第二个人（已三次复现）。
  3. tight 的代价是裁手脚；要"单人 + 全身"只能让画布比例接近深度图（参考会被纵向压缩）。

### 2.2 填空模板

```
<|构图|>竖构图，单人全身立绘，人物从画面顶端到底端占满画面，正面平视，四边留白极少<|/构图|>

<|身体|>身高约等于头高的 8 倍。她的双手叉在腰上，站姿与深度图一致。
（bodice, crop top）罩在胸部；（belt, sash）卡在腰上，正面垂下一条 V 形尾；（left sleeve）/（right sleeve）套在两条胳膊上；
（orb, pomander）挂在腰侧；两条腿外面是（trousers）；脚上是（shoes）。
画面里只有她一个人、一双手、两条手臂。<|/身体|>

<|bodice|>……材质 + 颜色 + 透明度 + 结构 + 可见行为（受光/断面/滴落）……<|/bodice|>
<|belt tail|>……<|/belt tail|>
<|trousers|>冰壳，有厚度、断口有断面、冰里嵌一串串深紫蓝菱形、表面挂水道……<|/trousers|>
…（每个 tag 一块）…
<|背景|>一整片干净的纯白，人物站在这片纯白上，白从画面一边连到另一边<|/背景|>
```

`<|身体|>` 块里**只写**：头身比一句、姿势一句（必须与深度图一致）、各件的**位置引用**（tag 名 + 在身上哪里）、数量锁一句。
**不要**在这里写材质（材质归各 tag 块）、不要写"从腰封下缘一直到脚踝"这类**位置范围**（会覆盖参考图视觉：写范围 → 冰只从大腿中段开始；不写 → 冰跟着参考图的裤子走）。

### 2.3 从旧 SOP 继承的十条硬规则（违反必翻车）

1. **否定式会招来**：`no hand in this area` → 手更清楚；「没有内裤」→ 内裤回来；「不能有灰雾」→ 出灰雾。禁项只能靠**改写形体**，`--negative` 在 cfg3.5 下 <1%。
2. **数值型参数基本无效**：`--image-strength`、`--negative`、Alpha 数值（写 0.70 与不写一样透，甚至反向）。唯一有效是**描述"背后能看到什么"**。
3. **大面深色用 HEX**；浅色/渐变回文字；**CMYK 不可靠**；**不写"两色交替"**。
4. **绝不给袖子写体量**（「很宽」「从肩到手腕」「垂到膝盖」→ 4–6 只手）。只写材质 + 归属 + 收口（「袖口收在金色宽镯上」）。
5. **材料段不写位置范围**（写「从腰封下缘一直到脚踝」→ 冰只从大腿中段开始）。
6. **要透形，先写"颜色被冲淡/半透明"，再点名**：写「深藏蓝」= 实心深色布，形状永远看不见；乳晕能透是因为有颜色差，阴唇难透是因为只有形状。
7. **数量锁只放对应块内**（双臂块内有效；放进整图 summary/构图 → 与色图物件槽位抢主体，裂成三人）。
8. **一版只改一个变量**；改之前先 dump 目标块整行原文。
9. **不要写画风段**（测试与结构验证阶段）：画风由 LoRA 触发词决定，写画风词是噪音；`anime_seinen @0.8` 是本项目主力。
10. **`--fast`（8 步/cfg1）只出"颜色型"细节**：乳头只有两片粉红、冰退成纱、冰鞋退成布鞋；要体积与真冰必须 `--no-fast --steps 24–50 --cfg 3.5`。

### 2.4 与 GrabTag 的接线

- 第一段（`<|身体|>`）写 **ref_tag 英文原词**作为检索键 → `active --prompt` 用它判断"哪些 tag 参与"。
- 每个 tag 块正文 = 该区 `paint_prompt` 的扩写（`paint_prompt` 本身 ≤18 词、一区一物、必带落点介词、至少一个颜色词；块内正文可写长，但也别超 160 字）。
- **tag 块只写"这块的材质/外观"**，不写姿势、不写镜头、不写背景、不写光照方向（六类禁用词）。
- `--color-map` 才画像素作用域；只给 `--layout` 会被 `moss_run.py` 自动转成色图（现网行为，`_layout_to_colormap`）——要纯文本控制就别传 layout。
- **⚠ 在 MiE 通道下禁止传 `--layout`**（2026-11-08 实测，`gt_p012_a`）：`--layout` 会把 11 个区拼成 `Region 1 (upper centre): … Region 11 (lower centre): …` 的整段文案注入提示词，模型把这套文案读成「分区展示」，直接画成**角色设定图**（画面里出现单独的袖子特写、无头躯干、腰封特写、一排鞋），人物本体还在但被挤到左下。
- **正确接法：只传 `--color-map regcap_<dir>.png`，不传 `--layout`**（`gt_p012_b`）：姿势百分百按深度图、服装纹样全对、单人；代价是**色图空区会长出多余物件**（右上角多一片袖子，因为 spec 的 `sleeve_r` 区落在空白处）→ 按姿势重标 spec 即可消除。

### 2.5 负面（固定，同系列一字不改）

```
worst quality, bad anatomy, watermark, jpeg artifact, multiple people, two women, duplicate
```
它是"方向"不是"清单"：CFG 的正负差值决定推离方向；换一版就改一次负向 → 无法归因。

### 2.6 写完自检（10 问，来自 08 §9.1）

模式定没定（多图有没有分工）→ 每主体七项齐没齐 → 接触点写了对象+位置没 → 衣/发/器物遮挡写了没 → 主光方向与暗部/亮部写了没 → 每材质有可见行为没 → **有没有写"没有 X"** → **有没有给袖子写体量 / 给材料写位置范围** → 颜色是 HEX 还是形容词 → **这一版只改了一个变量吗**。

### 2.7 出图后的三件事（必做）

1. `--prefix` 固定、`run_collect.py --run-dir <run> --prefix <prefix> --audit` 收成品 + 指标 + 审图表；
2. 看 `audit\_audit_sheet.png` 六块特写（脸 / 胸臂 / 左手 / 右手 / 胯腿 / 双脚）—— **手数以人眼为准**，mediapipe 对动漫图会漏检也会误报；
3. 指标记进 `run.json`（占高/占宽/比例/饱和/锐度/肤色/深色），跨版对比只比同一套口径。

### 5.3 步数与 control-strength

| 版本 | 步数 | control | 时间 | 锐度 | 饱和 |
|---|---|---|---|---|---|
| fast | 8 | 0.85/0.88 | 46.6 s | 359 | 53.8 |
| **24 步** | **24** | 0.85/0.88 | **96.8 s** | **770** | 71.6 |
| 50 步 | 50 | 0.85/0.88 | 205.0 s | 794 | 72.4 |
| 50 步 + 0.95 | 50 | **0.95**/0.88 | 205.1 s | 716 | 64.6 |

- **2 MP 画布下 24 步已饱和**（比 50 步仅差 3%，时间 47%）⇒ 要细节用 24 步，不要 50 步。
- `--control-strength` 提到 0.95 **不纠正局部摆放**，只让整体更"贴"且细节掉 10% ⇒ 默认 0.85 即可。
- **步数会改变"画不画某个部件"**：≥24 步时模型主动把鞋画出来并摆到看得见的位置；8 步时鞋被身体自然挡住、反而更贴深度图。

### 5.4 实景图转深度图：必须先压黑背景

用 `Depth-Anything-V2` 处理一张实景插画（背景有床、枕头、窗帘）→ 深度图把背景编码成"中景物体" → **成图里被画成大片白床单和白枕头**，`<|背景|>` 里写「没有床，没有窗帘」完全无效。

修法：抽完深度图后按亮度分位数压黑（本项目用 `p45`，非零像素约 50%），再线性拉伸到 0–255。
- 压黑后：白床单消失、背景恢复纯白，锐度 598 → 536（代价很小）。

### 5.5 横构图的处理

深度图是横构图（1728×969）、参考图是竖构图（1024×1824）时：
- **画布按深度比例**（`--w 1728 --h 976`），不要按参考比例，否则姿势被压成很小一条；
- 参考图 **contain 进画布居中补白**（本例 547×976 摆在 1728×976 中间），放弃 `MOSS_REF_ALIGN` 的零变形，优先保住构图。

### 5.6 运维：`hostbuf_file_reader_read failed` 的第一嫌疑是双实例

|---|---|---|---|---|
| 预处理（contain + 补黑） | 960×1280 → 缩进 1056×1408 居中、上下补黑 480 | 1056×1888 | 姿势对，但**上方留黑处会长出第二个人**（双人） | 435 |
| **原样（不缩放/不补黑/不裁）** | **960×1280 原封不动** | 1056×1888（按参考裁 alpha 后 1530×2720 → 1056×1872） | **姿势完全对、单人、无黑边、背景纯白** | 373（fast 8 步） |

- 结论：**深度图不要为了凑画布比例去 contain/tight/补黑**，直接把原图交给 `--depth-map`，让 MOSS 内部 fit；画布只按**参考图裁掉 alpha 空白后**的比例来定。
- 前提：深度图背景本身要干净（近黑渐变或纯黑）。若源图是实景（床/窗帘），仍要按 §5.4 先压黑。
- 参考图裁 alpha：`im.split()[-1].getbbox()`（本例 1538×2724 → 1530×2720），再按 ≤2 MP 缩到 16 的倍数（1056×1872）。
### 5.8 画布比例取**深度**比例、高度取**参考**高度（推荐）

| 版本 | 画布 | 深度 | 结果 | 锐度 |
|---|---|---|---|---|
| `sx6_a` | 1056×1888（比例 0.564 = 参考比例） | 原样 960×1280（0.75，被 fit 拉伸） | 姿势对、单人，但人物撑满、贴边 | 373 |
| **`sx6_b`** | **1216×1632（比例 0.745 ≈ 深度 0.75）** | 原样 960×1280（**几乎零变形**，只缩 1.27×） | **姿势全对、全身入画、留白均衡、比例自然、单人** | 275 |

做法：
1. 参考图裁掉 alpha 空白（`im.split()[-1].getbbox()`）→ 得 `1530×2720`；
2. **高 = 参考裁剪高在 2 MP 内的最大 16 倍数**（本例 1632），**宽 = 高 × 深度宽高比**（1632×0.75 = 1224 → 取 16 倍数 1216，比例 0.745）；
3. 参考图 **contain 进画布居中补白**（918×1632，左右各 149）；
4. 深度图**原样**交 `--depth-map`，不缩放不补黑。

⇒ 这样深度与画布的比例几乎一致，深度**零变形**；高度又跟着参考图走，人物不会被压扁或撑满。**比"画布 = 参考比例"更稳。**
